# 모아 · JEV Workplace

회사 포털을 위한 채팅형 인터랙티브 UI 프로토타입입니다. 자연어는 **JEV만** 판단하고, 서버 코드가 더미 데이터로 json-render Spec을 구성합니다. 생성형 LLM을 호출하거나 답변 텍스트를 생성하지 않습니다. 업무와 무관한 요청은 **사내 LLM으로 라우팅됨 / 미연결** 카드만 표시합니다.

## 실행

```sh
npm install
cp .env.example .env
# .env의 JEV_KEY를 TypeSafe API 키로 설정
npm run dev
```

http://localhost:3004 에서 확인합니다. 이 워크스페이스에서는 키가 없을 때 기존 project3 → project2 → project1의 `.env`에서 JEV_KEY 또는 TYPESAFE_API_KEY만 읽습니다. 키는 서버에서만 사용하며 복사하거나 클라이언트에 전달하지 않습니다. 새 환경에서는 자체 `.env`를 사용하세요.

```sh
npm run build
npm start
npm test
npm run test:live # 개발 서버 실행 및 유효한 JEV 키 필요; 실제 API 비용 발생
```

## 대화 예시

- `오늘 점심 뭐 나와?` → `아침부터 저녁까지 다 보여줘` → `이번 주는?`
- `오늘 일정 보여줘` → `이번 주 전체` → `내일은?`
- `오늘 날씨 알려줘` → `습도만 볼래` → `내일은?`
- `오늘 점심이랑 일정 같이 보여줘` → 식단 + 일정 카드
- `금요일 오후 반차 쓰고 싶어` → 날짜와 종류가 채워진 신청 폼
- `내 연차 얼마나 남았어?` / `휴가 신청 내역 보여줘`
- `내일 회의실 예약하고 싶어` → 회의실별 시간 선택 + 예약
- `최근 사내 공지 보여줘` → 펼칠 수 있는 공지 목록
- `파이썬으로 정렬 함수 만들어줘` → 사내 LLM 라우팅 카드 (실제 호출 0회)

각 자연어 요청마다 사용자 말풍선과 별도의 인터랙티브 답변 카드가 추가됩니다. 기존 카드의 탭과 날짜 선택기는 모델 호출 없이 즉시 바뀌며, 최신 카드의 선택 결과가 후속 자연어 요청에 전달됩니다. 휴가 폼의 작성 사유도 같은 업무의 후속 요청으로 이어집니다. 카드 아래 `처리 과정`에서 네트워크 + 판단을 포함한 응답 시간, USD·원화 예상 비용, JEV 답변, 토큰 사용량, json-render Spec을 볼 수 있습니다.

## 구조

```text
입력 + 현재 업무 문맥
  → 서버 /api/interpret
  → TypeSafe /v1/systemone (하나의 요청에 독립적인 Choice 질문)
  → 기능 · 기간 · 날짜 · 식사 · 날씨 항목 · 휴가 화면/종류
  → 검증된 코드가 더미 데이터 조회 및 flat Spec 구성
  → @json-render/react Renderer → 채팅 안의 업무 UI
```

- `server/jev.js`: 의미 판단 질문, TypeSafe 요청/응답 검증. 키워드 라우터나 가짜 AI 폴백 없음.
- `server/domain.js`: 날짜 계산, 더미 데이터, 검증, Spec 구성.
- `server/index.js`: API 및 Vite 서버, 휴가/예약 저장과 입력 검증.
- `src/App.jsx`: 채팅, 로컬 대화 내역, 문맥 전달, 처리 과정 패널.
- `src/cards.jsx`: json-render 컴포넌트 레지스트리 및 인터랙티브 업무 카드.
- `tokens.css`: 디자인 토큰.

**json-render의 실험적 Gateway composer는 사용하지 않습니다.** 회사 포털은 허용된 업무별 UI가 정해져 있으므로 JEV의 typed 판단을 직접 받아 코드로 Spec을 조립합니다. json-render `0.21.0`을 고정해 실제 렌더러를 사용합니다. Gateway 계정 없이 TypeSafe 키로 실행할 수 있습니다.

## 데모 범위

- 식단, 날씨, 일정, 직원 정보, 공지는 모두 합성 데이터. 날짜는 서울 시간 기준 현재 날짜입니다.
- 자연어 날짜 후보는 이틀 전부터 60일 후까지. 최대 두 업무를 한 요청으로 표시하며 복합 요청은 같은 날짜/기간을 공유합니다.
- 주간 식단·일정·날씨 지원. 휴가는 하루/반차 신청, 회의실은 날짜별 1시간 예약입니다.
- 휴가 확정·취소, 예약·취소는 `.data/demo.json`에만 저장. 중복 신청, 중복 예약, 연차 부족, 잘못된 날짜를 서버에서 검사합니다.
- 연차는 15일에서 시작하며 승인 대기분도 잔여량에서 차감합니다. 취소하면 복원됩니다.
- 대화와 폼 초안은 이 브라우저의 localStorage에 저장됩니다. 각 대화의 × 버튼으로 삭제할 수 있습니다.
- 실제 SSO·권한·사내 API·실시간 날씨·캘린더 연동은 없습니다. 서버는 localhost에만 바인딩하는 단일 데모 사용자 환경입니다.
- JEV 연결 오류는 오류 카드로 표시하며, 이때도 사이드바 메뉴를 통해 UI를 둘러볼 수 있습니다.
- JEV 판단은 확률적입니다. 운영 적용 전 실제 사내 표현으로 별도 평가해야 합니다.

## 검증

`npm test`는 주간 날짜 경계, 식사 범위, 복합 카드, LLM 라우팅, 취소 후 잔여 복원, 날짜 검증, 신청 중복 방지, 예약 충돌/취소를 검사합니다. 액션 테스트는 임시 데이터 디렉터리를 사용해 데모 데이터를 변경하지 않습니다.

`npm run test:live`는 실제 JEV로 13개 시나리오를 평가합니다. 2026-09-21 검증에서 13개 모두 통과했으며 약 0.2–0.6초의 JEV 왕복 시간(네트워크 + 판단)이 관측됐습니다. 지연 시간은 네트워크와 서비스 상태에 따라 달라집니다.

문장별 UI 차이와 조합 전 컴포넌트 구조는 [UI-CATALOG.md](./UI-CATALOG.md)에 정리했습니다. `npm run test:semantic`으로 문맥 전환·부정 표현을 포함한 30개 실제 JEV 시나리오를 재검증할 수 있습니다.
